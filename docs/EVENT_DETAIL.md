# 이벤트 상세 페이지 프론트 계약

`이벤트 상세 페이지`는 서버의 `design_variant`, `rewards`, `product_display` 응답만으로 화면 구성을 결정합니다.

- `product_display.enabled=false`이거나 이벤트 참여 상품 응답이 비어 있으면 상품 영역을 렌더링하지 않습니다.
- `PRODUCT_GRID`는 상품을 2열/4열 그리드로, `MARKET_CAROUSELS`는 `market_id`별 가로 캐러셀로 표시합니다.
- `MARKET_CAROUSELS`의 참여 마켓 헤더는 이벤트 상품 응답의 `market_profile_image_url`, `market_description`, `market_follower_count`를 사용해 마켓 아이콘·설명·팔로워 정보를 함께 표시합니다.
- 두 방식 모두 `limit=12`, `offset={누적 상품 수}`로 무한 스크롤합니다.
- 정렬과 마켓·카테고리 필터 선택지는 서버 응답만 사용하고, 선택값을 이벤트 상품 API에 전달합니다.
- `이벤트 보상`은 `sequence` 순서로 표시하며 각 쿠폰·포인트 버튼은 자신의 `reward_row_id` 발급 API를 호출합니다. 비로그인 회원은 로그인 화면으로 이동합니다.
- 쿠폰 여러 개와 포인트가 함께 내려오면 보상 종류별 티켓을 모두 노출하며, 배열이 비어 있으면 혜택 영역을 렌더링하지 않습니다.
- `BENEFIT_FOCUS`, `MARKET_STORY` 등 `design_variant`는 히어로와 혜택의 시각 표현을 바꾸되 데이터 계약은 공유합니다.

백엔드가 아직 배포되지 않은 로컬 화면에서는 알려진 미리보기 이벤트 ID의 조회·상품 API가 `404 Not Found`일 때만 동일 계약의 더미를 표시합니다. 알 수 없는 이벤트 ID, `500`, 응답 계약 오류와 정상 빈 응답은 더미로 바꾸지 않습니다. 보상 발급처럼 상태를 변경하는 요청은 더미 성공으로 위장하지 않습니다.

이전 고정 UI였던 `기간 안내`, `빠른 출고`, `안심 구매`, `이벤트 상품 전체보기`는 사용하지 않습니다.
