# 주문·배송비·환불 UI 검증

## 현재 구현

- 마켓별 배송비 설정을 판매자 화면에서 조회·저장하며 상품 안내·주문 견적에 실제 설정을 반영한다. 쿠폰·포인트는 상품 금액에만 적용한다.
- 주문서의 쿠폰·포인트 아래 결제수단 영역을 배치하고 Toss widget 결제금액을 저장된 주문 금액과 검증한다. 결제 준비 상태는 같은 주문으로 재시도한다.
- 구매자·판매자·관리자의 최초 결제금액, 실제 간편결제 제공자와 배송정보를 서버 데이터로 표시한다. 주문번호 복사와 좁은 화면 줄바꿈을 지원한다.
- 관리자 환불 견적·사유·회수 확인·확인 팝업·완료 요약을 공통 디자인 시스템과 primary 색상으로 통일한다. 진행 중에는 견적을 갱신하고 완료 시 주문 조회를 갱신한다.
- 단순변심은 배송비 유지, 판매자 귀책은 배송비 포함 환불이다. 복원 포인트·쿠폰 상태는 서버 완료 결과를 표시한다.
- 고정 하단 메뉴를 유지하며 화면과 팝업의 하단 여백·스크롤·포커스를 조정했다.

## 실제 통합 확인

로컬 Docker 웹 13000/API 18083/MySQL/Temporal/worker와 실제 Toss TEST API를 사용했다. 카카오페이 인증은 사용자가 직접 진행했다. 결제·환불 PG 응답을 모킹하지 않았다. 배송·회수는 테스트 송장 및 확인 절차로 처리했으며 실제 물류 연동 검증은 아니다.

- 기존 최종 촬영 주문 55: 상품29,900 − 쿠폰2,990 − 포인트1,000 + 배송비3,000 = 승인28,910원. 전체 상품 환불25,910원, PG 잔액3,000원·취소DONE1건, 포인트1,000P·쿠폰 복원.
- 최신 복구 처리 검증 주문193: 같은 금액의 승인·환불. 환불 SUCCEEDED1회, 동일 완료 요청 재호출 후 PG취소1건·포인트1,000P 유지. 처리 시작부터 로컬 완료1.277초(DB timestamp).
- 촬영용 마켓 설정은 주문 생성 직후 원래 설정으로 복구했다. 주문에 저장된 배송비는 유지된다.
- 동시 실행·결과 불명확·철회 등 실패 경로는 백엔드 실제 MySQL + PG 테스트 대역으로 검증했다. 영상은 정상 동작을 보여준다.
