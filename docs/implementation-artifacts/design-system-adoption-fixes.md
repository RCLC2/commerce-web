# 디자인 시스템 전면 적용 보완

- 프런트엔드: `commerce-web-readability`, `feat/design-system-readability-ko`
- 백엔드 연동 변경: `commerce-ui-support`, `feat/commerce-ui-support` (기준 `c2458cb5`)
- 서비스명 `commerce`, 상품·마켓·브랜드명은 유지한다. 본문의 안내·상태 문구를 한국어로 표시한다.
- 기존 메뉴 순서, 화면의 최대 폭과 주요 콘텐츠 배치를 유지한다.

## 요청별 변경

| 요청 | 반영 내용 |
| --- | --- |

| 버튼 hover | 화면에 남은 자체 버튼을 `Button`으로 이동했다. 버튼·버튼형 링크에 hover, pressed, focus, disabled 규칙을 공유한다. 캐러셀·검색·리뷰·운영 화면 조작에도 적용했다. |
| 페이지 마크 통일 | `PageHeading`으로 탐색·계정·주문 화면의 제목, 아이콘, 설명을 통일했다. 아이콘은 장식으로 처리해 제목을 중복 읽지 않는다. |
| SPA 이동 | 기존 `Link`·라우터 이동을 유지하며, 상품 상세 HTML의 내부 링크도 클라이언트 라우터로 연결했다. 외부 링크, 새 탭, 다운로드, 보조 키 클릭은 브라우저 동작을 유지한다. 공통 로딩 화면을 추가했다. |
| 메뉴 애니메이션 | 공통 `Drawer`가 240ms 슬라이드·배경 전환을 제공한다. 닫히는 동안에도 전환을 유지하고 Escape, 스크롤 잠금, 포커스 복귀, 동작 줄이기 설정을 지원한다. |
| 홈 아이콘·글자색 | 홈일 때만 채움 배경과 밝은 아이콘·글자색을 사용한다. hover에도 글자 대비를 유지한다. |
| 판매가 여백·카드 높이 | 가격 라벨, 할인 정보, 최종 금액을 같은 구조로 표시하고 판매가 중복 표기를 제거했다. 할인 유무에 관계없이 가격 영역을 정렬한다. |
| 마켓명·상품명 구분 | 마켓 아이콘과 작은 보조색 이름, 굵은 상품명으로 위계를 구분한다. |
| 카테고리 페이지 선택 | 공통 `Pagination`으로 번호 선택·직접 입력을 제공한다. 카테고리와 페이지는 URL에 남아 뒤로가기·새로고침에도 유지된다. 백엔드는 `total`, `total_pages`를 반환하고 범위 밖 요청을 마지막 페이지로 보정한다. 이전 API 응답도 다음 페이지 여부와 직접 입력으로 호환한다. |
| 장바구니 수량·옵션 변경 | `QuantityStepper`, `Dialog`, `Field`, `Select`, `Notice`를 사용한다. 저장 중 중복 조작을 막고 응답의 실제 가격·수량으로 합계와 주문 대상 ID를 갱신한다. 품절 옵션과 가용 재고를 확인한다. |
| 주문 상세 한국어 | 제목을 ‘주문 상세’로 표시하고 주문 번호를 구분했다. 결제·주문·배송 상태와 버튼은 한국어로 표시한다. |

| 404 | 한국어 안내, 홈·상품 목록 이동 버튼이 있는 공통 스타일의 404 화면을 추가했다. |
| 좁은 모바일 화면 | 320px에서 commerce 로고가 줄바꿈되지 않도록 검색 진입을 아이콘으로 제공한다. 판매자·관리자 바로가기는 메뉴에서도 제공한다. 마이페이지의 긴 상품명·금액 넘침과 이메일 줄바꿈, 주문서 금액 줄바꿈을 보정했다. |
| 주문서 안내 | 쿠폰 ID 등 내부 구현 설명을 실제 사용 조건 안내로 바꿨다. 신규 배송지 등록 화면이 없는 상태에서 등록하라고 안내하던 문구를 주문 불가 사유로 바로잡았다. |

## 장바구니 서버 계약

기존 서버에는 장바구니 추가·조회만 있어 프런트엔드만으로 저장 기능을 완성할 수 없었다. 별도 백엔드 워크트리에 다음 변경을 포함했다.

`PATCH /api/v1/cart/items`

```json
{ "cart_item_ids": [1, 2], "option_id": 20, "quantity": 3 }
```

- 인증된 회원 소유의 동일 상품·옵션 그룹만 수정한다.
- 트랜잭션에서 항목을 잠그고, 가장 작은 기존 ID를 유지하며 중복 저장 행을 합친다.
- 이미 주문 중인 항목은 수정하지 않는다.
- 활성 옵션과 가용 재고를 확인하고 다른 장바구니 항목의 동일 옵션 수량도 고려한다.
- 현재 판매가와 옵션 추가금을 서버에서 계산한다. 클라이언트 가격은 받지 않는다.
- 변경과 이벤트 기록 중 하나라도 실패하면 롤백한다.
- 성공 시 기존 장바구니 응답과 같은 형식의 단일 저장 행을 반환한다. 프런트엔드는 이 ID로 주문한다.

## 검증

- 프런트엔드 린트·타입 검사·프로덕션 빌드 통과.
- 단위 테스트 48개 파일, 244개 테스트 통과. 장바구니 그룹 수량 저장, 옵션·품절 처리, 실패 후 값 유지, API 전송, 페이지 입력 범위, 본문 링크 이동을 포함한다.
- 기존 카테고리 탐색·코디·온보딩 브라우저 테스트 5개 통과.
- 디자인 시스템 문서 타입 검사와 정적 HTML 7개 재생성 통과. PageHeading·Pagination·Drawer 실행 예시를 추가했다.
- 백엔드 주문·상품·API 패키지 테스트와 `go vet` 통과. 중복 그룹 통합, 잘못된 그룹, 주문 중 항목, 재고 부족, 이벤트 저장 실패의 롤백, 추가금, 페이지 범위를 검증했다.
- API 실행 파일 빌드 통과. 신규 HTTP 라우트가 기존 애플리케이션에 연결된다.
- 실제 브라우저에서 버튼·링크 hover 배경 전환, 홈 버튼의 밝은 글자·아이콘, 메뉴의 240ms 전환·포커스 복귀를 확인했다.
- 홈·탐색·검색·상품/마켓/이벤트 상세·장바구니·주문서·계정·인증·404·판매자 상품·관리자 회원 등 25개 화면을 1440px·390px·320px에서 확인했다. 총 75개 화면에서 로딩 완료 후 가로 넘침이 없었다. 당시 가격 영역은 128px였으며, 이후 아래 할인 가격 여백 보정에서 축소했다. 최종 주문서 문구 보정 뒤 320px 화면을 다시 확인했다.
- 마이페이지 필터의 선택 전후 x 좌표·폭이 일치했다. 장바구니→마이페이지→쿠폰→홈 이동에서도 문서의 `performance.timeOrigin`이 동일했다.
- 카테고리 2페이지 선택 → 4페이지 직접 입력 → 뒤로가기로 2페이지 복귀를 확인했다. 요청의 page 값과 URL이 일치하고 문서의 `performance.timeOrigin`이 유지됐다. 상품 상세 본문의 내부 링크 이동에서도 같은 결과였다.
- 장바구니 수량 1→2 저장, 옵션 변경 후 추가금이 반영된 41,000원·수량 1 응답과 화면 합계 일치를 확인했다. 이 브라우저 검증의 저장 응답은 테스트용 모의 API다.
- 없는 경로의 HTTP 상태는 404였다.

## 실행 범위와 남은 의존성

두 워크트리의 변경은 아직 커밋·병합·배포하지 않았다. 장바구니 저장과 카테고리 전체 페이지 수를 실제 서비스에서 사용하려면 백엔드 변경도 함께 반영해야 한다. 화면 검증은 통제된 API 응답으로 수행했고, 실제 데이터베이스를 사용한 저장·결제 통합 검증은 별도다. 백엔드 테스트는 서비스 테스트와 SQL 모의 응답을 사용해 트랜잭션 commit·rollback을 확인한다.

최종 확인에서도 `http://localhost:8080/api/v1/categories`는 연결 거부였다. 실제 API를 사용한 상품·주문 조회 및 신규 저장 성공은 확인할 수 없는 상태다. 브라우저 경로의 모의 응답은 서버 측 상품 상세 초기 조회나 추천 구성을 검증하지 않는다.

후속 Docker 실행 요청에서 로컬 DB·API·프런트엔드를 함께 실행했다. 로그인, 상품 담기, 수량·옵션 저장과 새로고침 후 유지, 카테고리 페이지 보정을 실제 DB로 추가 확인했다. 서버에서 실행하는 상품 상세 조회의 내부 API 주소도 보정했다. 실행 방법과 외부 결제·업로드 연동 한계는 [Docker 사용 기록](../docker-preview.md)에 정리한다. 앞의 API 연결 불가 기록은 Docker 기동 전의 상태다.

이전 점검의 배송지 신규 등록, 주문 응답의 배송지 누락, CMS 임의 API 주소 처리 등은 이번 디자인 시스템·요청 목록의 변경으로 해결됐다고 간주하지 않는다. 이전 기록은 `design-system-readability-ko.md`에 남아 있다.

화면·검증 로그는 Git에서 제외되는 `output/playwright/adoption-*`에 저장한다.

## 할인 가격 여백 보정 — 2026-09-06

- `ProductCardPrice`의 128px 최소 높이와 60px 할인 정보 공간 때문에 최종 가격 앞에 큰 공백이 생겼다. 라벨 바로 아래에 최종 가격을 두고, 할인율·비교 가격은 다음 줄에 묶었다. 기본 높이는 100px로 줄이고 긴 쿠폰 문구는 자연스럽게 줄바꿈하도록 했다.
- Docker의 웹 컨테이너만 다시 빌드해 반영했다. 실제 홈을 1440px·390px·320px에서 확인했고, 320px 카테고리의 6개 가격 영역은 모두 100px 높이와 동일한 최종 가격 위치를 유지했다. 가격 영역과 페이지의 가로 넘침은 없었다.
- 가격 계산·렌더링 테스트 11개, 변경 컴포넌트 린트와 Docker 프로덕션 빌드가 통과했다. 화면 캡처는 `output/playwright/price-*`에 저장한다.
- 별도 발견: 홈이 요청하는 `/icons/home-category/hats.svg` 파일이 없어 404가 발생한다. 이번 가격 CSS 보정 범위에는 포함하지 않았다.

### 후속 요청: 할인 정보 가로 정렬

- 라벨·할인율·비교 가격을 가로로 배치하고 최종 금액을 4px 아래에 표시했다. 100px 최소 높이도 제거했다. 상품 이미지·마켓명·상품명 위치는 유지한다.
- Docker 웹 이미지를 다시 빌드했다. 실제 홈의 데스크톱 가격 영역은 64px로 줄었고, 390px·320px 모바일에서도 확인했다. 320px에서는 할인 정보가 자연스럽게 줄바꿈되어 84px가 되며 가격 영역과 페이지의 가로 넘침은 없다.
- 가격 컴포넌트 테스트 3개, 린트, Docker 프로덕션 빌드가 통과했다. 캡처와 빌드 로그는 `output/playwright/price-horizontal-*`에 저장했다.

### 최종 배치: 참조 이미지 적용과 상품명 정렬

- 가격 영역의 배경 박스와 12px 내부 여백을 제거해 상품명과 왼쪽 시작선을 맞췄다. 위에는 ‘판매가’, 아래에는 할인율·비교 가격 묶음과 강조한 ‘할인가 + 최종 금액’을 가로로 배치한다. 쿠폰이 있으면 ‘쿠폰 최적가’를 표시한다. 좁은 화면에서는 묶음을 왼쪽으로 줄바꿈하며 최소 높이는 강제하지 않는다.
- Docker에 반영한 뒤 실제 홈의 1200px·390px·320px 화면에서 상품명과 가격 라벨의 왼쪽 좌표 일치와 가격 영역의 넘침 없음을 확인했다. 가격 컴포넌트 테스트 3개·린트·프로덕션 빌드가 통과했다. 최종 캡처는 `output/playwright/price-reference-*`에 저장했다.
