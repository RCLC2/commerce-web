## 공통 컴포넌트 적용 계약

- 기존 운영 입력은 `inputVariants`를 공유하되 페이지에서 지정한 폭과 그리드는 유지한다. 입력 높이는 44px 이상으로 정리한다.
- 주문 상태와 정산 상태는 맥락에 맞게 표시한다. 예를 들어 `PAID`는 주문에서 ‘결제 완료’, 정산에서 ‘지급 완료’다. 전송 값은 유지한다.
- 공통 상태 배지는 12px 보조 글자와 의미 색상을 사용한다.
- 운영 모달은 기존 너비·상단 제목·하단 작업 위치를 유지하면서 공통 오버레이의 포커스 관리 규칙을 공유한다.

## 적용 범위

- 쇼핑: 헤더·메뉴·하단 탐색, 홈, 카테고리, 검색·상품 목록, 상품 상세, 마켓·피드, 이벤트, 오늘의 코디.
- 회원: 로그인·가입·온보딩, 좋아요, 장바구니·주문서, 결제 결과·주문 상세, 마이페이지·프로필·쿠폰·리뷰.
- 운영: 판매자 상품·주문·정산·재고·광고·리뷰, 관리자 회원·마켓·상품·주문·정산·콘텐츠·실험·감사 이력.
- UI 위치와 API 전송 계약을 유지했다. 상품·마켓 이름, 운영자 정의 코드, 이미지 출처, HTML·API·URL 같은 기술 식별자는 원문을 유지한다.
- 원본의 `.env.local`도 새 워크트리에 복사했다. 현재 값은 로컬 API를 가리키며 Git 추적 대상이 아니다.

## 함께 수정한 표시·조작 문제

| 문제 | 수정 |
| --- | --- |
| 8~11px 안내 글자, 흐린 보조색·입력 경계 | 12px 이상 안내와 대비가 검증된 콘텐츠·입력 토큰 적용 |
| 영어 주문 상세·광고 표기·운영 필드·상태 코드 | 한국어 표시 함수와 공통 컴포넌트로 정리 |
| 주문의 `PAID`가 ‘지급 완료’로 표시됨 | 주문은 ‘결제 완료’, 정산은 ‘지급 완료’로 구분 |
| 판매자 하위 메뉴에서도 홈 메뉴가 함께 선택됨 | 판매자 홈의 일치 조건 수정, 현재 메뉴에 `aria-current` 지정 |
| 링크 안에 버튼이 중첩됨 | `ButtonLink`로 하나의 탐색 요소만 렌더링 |
| 운영 모달의 포커스 이동·복원 부족 | 공통 오버레이 관리 사용. 중첩 창의 Tab·Escape와 포커스 복원 확인 |
| 긴 모바일 메뉴 이름·금액이 잘리거나 분리됨 | 메뉴의 두 줄 표시와 접근성 이름 유지, 금액 줄바꿈 방지 |

## 추가로 확인할 문제

| 우선순위 | 현상과 영향 | 근거 및 확인 수준 |
| --- | --- | --- |
| 높음 | 현재 로컬 API와 실험 서버가 실행되지 않아 실제 상품·회원·운영 데이터를 읽을 수 없음 | 위 연결 검사에서 HTTP 응답 없이 연결 거부. 실제 결제 승인과 서버 저장은 검증하지 못함 |
| 높음 | 배송지가 없는 회원에게 마이페이지에서 배송지를 등록하라고 안내하지만 신규 등록 UI가 없음. 주문서의 주문 버튼도 배송지가 없으면 비활성화됨 | `src/components/checkout-page.tsx`의 `!defaultAddress` 조건과 `src/components/my-page.tsx`의 기존 주소 편집 조건. `src/lib/api/customer.ts`에는 주소 조회·수정만 있음. 프론트 코드에서 확인 |
| 중간 | 주문서는 배송지가 주문 정보로 저장된다고 안내하지만 고객 주문 상세는 항상 배송지를 확인할 수 없다고 표시함 | `checkout-page.tsx`는 `shipping_address`를 전달한다. `order-detail-page.tsx`의 배송지 영역은 고정 안내이며 응답 주소를 표시하지 않는다. 서버 저장 여부는 미검증 |
| 중간 | 관리자가 홈 상품 영역에 임의 API 주소를 등록해도 해당 주소를 호출하지 않음 | `home-page.tsx`의 `productsForHomeSection`은 프로모션·최신 상품만 분기하고 나머지는 인기 상품으로 처리한다. 관리자 콘텐츠 폼은 API 주소를 자유 입력받음. 코드에서 확인 |
| 낮음 | 할인 없는 상품의 같은 가격이 두 번 표시됨 | `product-card-price.tsx`는 일반 가격 상태에서 기본가와 최종가를 함께 렌더링한다. 기존 가격 정책과 테스트를 유지했으며, 중복 표시 제거는 별도 판단 필요 |
| 낮음 | 실행 안내가 저장소에 없는 `.env.example` 복사를 요구함 | `README.md`의 환경 설정 안내와 Git 파일 목록 불일치. 이번 실행은 기존 `.env.local`을 복사함 |

### 기존 문서에만 남아 있는 서버 확인 사항

`docs/BACKEND_CONTRACT_GAPS.md`에는 프로필 수정 값 미저장, 관리자 취소 사유 미저장 등의 기록이 있다. 이번에는 API 서버가 없어 재현하지 못했다. 특히 이 문서의 ‘주문 생성에 배송지 필드가 없다’는 설명은 현재 프론트의 `shipping_address` 전송 코드와 다르므로 서버 버전과 함께 문서를 갱신해야 한다. 기존 기록을 현재 장애로 단정하지 않는다.

- `src/app`의 46개 페이지가 빌드 대상이다. 페이지 라우트·메뉴 대상·API 요청 경로를 재구성하지 않았다.
- 동일한 검증용 API 응답으로 기존 앱과 새 워크트리의 최종 프로덕션 빌드에서 7개 화면을 1440px·390px로 비교했다: 홈, 로그인, 상품 상세, 장바구니, 주문 상세, 판매자 상품, 관리자 회원. 14개 모두 본문 시작 x/y·폭, 하단 7개 메뉴 순서가 유지됐고 화면 전체 가로 넘침과 오류 안내가 없었다.
- 검증용 이미지와 응답은 브라우저에서만 사용했다. 상품·회원 데이터나 운영 서버 상태를 변경하지 않았다.
- 브라우저에서 상품 등록 → 상세 HTML 편집 → Escape를 확인했다. 2개 창 중 최상단 창만 닫히고 ‘상세 HTML 편집’ 버튼으로 포커스가 돌아왔다. 실제 상품은 등록하지 않았다.
- 광고 브라우저 테스트는 홈·검색 광고를 지나 상품 상세 단계에서 실패했다. 광고 응답만 대체하는 기존 테스트가 실제 상품 API에 의존하고, 해당 서버가 연결되지 않아 상품 상세 광고 영역을 렌더링하지 못했다. 광고 컴포넌트 단위 테스트는 한국어 광고 표기를 포함해 통과했다.

검증 파일은 `output/playwright/`에 있다. 실제 서버 통합 테스트와 토스 결제 승인은 서버가 준비된 환경에서 별도로 확인해야 한다.
