# 반품 주소 저장 영역·입력 안내 개선 검증

> 이 문서는 해당 날짜·작업 범위의 검증 이력이다. 현재 구현·API 계약·PR 반영 구분·최종 영상·테스트 범위는 [2026-10-24 최신 안내](return-pickup-address-20261022.md)를 기준으로 한다. 과거 실제 Toss TEST 검증과 최신 PG 대역 검증을 합쳐 설명하지 않는다.

2026-10-22. 기존 미커밋 변경을 보존했고 커밋·푸시는 하지 않았다.

## 변경

- 기본 반품 주소 폼의 저장 안내·오류·버튼을 불투명 배경의 하단 sticky 영역으로 묶었다. 짧은 화면에서 입력 양식을 스크롤해도 저장 영역을 확인할 수 있다.
- 주소 편집기를 펼치면 해당 영역으로 스크롤한다. 입력란에 초점이 이동할 때 저장 영역에 가려질 위치라면 입력란을 화면 안으로 이동한다.
- 우편번호의 숫자 5자리 조건을 기본 안내로 표시했다. 항목을 벗어난 뒤에는 잘못된 입력을 해당 필드의 오류 메시지·오류 테두리·`aria-invalid`로 연결한다. 수정하면 즉시 해제된다.
- 저장 버튼에 현재 저장 불가 이유 또는 저장 가능 안내를 연결했다. 필수 값·기존 길이·우편번호 조건을 만족해야 저장할 수 있다. 서버의 저장 실패와 저장 후 재조회 대기 안내도 유지했다.

## 검증

- 관련 Vitest 4개 파일 53건 통과. 미등록·실제 조회 장애·잘못된 우편번호·공백 수령인·유효 입력·저장 후 재조회·중복 저장 방지를 포함한다.
- TypeScript, 변경 파일 ESLint, `git diff --check`, 실제 촬영용 Next 프로덕션 빌드 통과.
- Chromium 1440×720, 390×844, 360×640에서 저장 영역이 모달 스크롤 영역을 벗어나지 않음을 확인했다.
- 360×640에서 스크롤 4회 동안 저장 영역 상단은 모두 y=523px이었다. 다섯 입력란에 초점을 차례로 이동해 저장 영역에 가려지지 않는 것도 확인했다.
- 실제 로컬 API·DB에서 우편번호 `0623` 입력 → 필드 오류·저장 비활성화 → `06236`으로 수정 → 오류 해제·저장 활성화 → PUT 200·GET 200 → 저장 완료 요약을 확인했다.
- 전용 테스트 DB의 마켓 1에 반품 주소 1건을 실제 등록했다. 추가 결제·주문·배송·환불 처리나 DB 마이그레이션은 수행하지 않았다.
