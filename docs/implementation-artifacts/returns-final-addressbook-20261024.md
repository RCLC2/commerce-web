## 저장 결과 대조

- 주문 `UI-RETURNS-partial-2c11af99`, 반품 `65`, 수거 `55`. 최종 주문 상태 `RETURN_COMPLETED`, 반품 `COMPLETED`, 수거 `RECEIVED`.
- 구매자는 주소록 `48`의 회사 주소를 선택했다. 신청 수거지와 수거 건의 수거지에서 수령인·전화번호·우편번호·주소·상세 주소 5개 필드가 일치했다.
- 판매자는 주소록 `50`의 반품센터를 선택했다. 마켓 기본 반품 도착지와 수거 건의 도착지에서 같은 5개 필드가 일치했다. 양쪽 모두 주소를 직접 입력하지 않았다.
- 옵션 2개를 모두 검수했다. 첫 옵션만 검수한 시점에는 환불 준비 완료로 전환하지 않았고, 모든 옵션을 검수한 뒤 환불액을 조회했다.
- 재입고 합계 3개. 네이비 재고 `100→102`, 블랙 `100→101`을 API 응답으로 대조했다.
- 상품 금액 30,000원, 사용 포인트 1,000P, 최초 결제액 29,000원. 무료배송 상품의 단순변심 전체 반품으로 최초 발송비 3,000원·회수비 3,000원을 반영해 결제수단 환불액 23,000원, 복원 포인트 1,000P로 완료했다.
- PG 테스트 대역의 취소 호출 1회, 취소액 23,000원, 잔액 6,000원이다.
- 구매자 화면은 수동 상태 새로고침 0회·문서 재로딩 없이 완료로 갱신됐다. 신청 후 내역 영역, 환불 상세 이동 후 상세 영역의 초점도 확인했다.

## 검증 경계와 증거

실제 로컬 Commerce 프로덕션 화면·인증·API·Docker MySQL을 사용했다. 배송 완료 주문과 최초 승인 결제는 합성 fixture로 준비했고, PG 취소는 HTTP 테스트 대역으로 처리했다. 새 Toss 테스트 결제 인증·실제 PG 취소·실물 택배 수거를 검증한 영상은 아니다. 택배 진행 결과는 판매자 화면에서 직접 기록했다.

이 실행에서는 전체 브라우저 흐름과 최종 저장 결과를 새로 검증했다. 단위 테스트·모바일 검사·빈 DB 마이그레이션·Down/Up을 재실행한 것은 아니다. 앞선 관련 62개 테스트와 모바일 검사는 [주소 요약·초점 검증](return-address-summary-focus-20261023.md), D1~D3 자동 통합 검증은 [별도 결과](returns-d123-verification-20261023.md)로 구분한다.

같은 영상 폴더에 다음 증거를 보관한다.

- `verification.json`: 양쪽 주소 5개 필드, 수량·재고·환불·포인트·PG 호출 결과.
- `buyer-submission-focus.txt`, `buyer-auto-completion-evidence.txt`: 초점 및 자동 갱신 확인.
- `timeline.json`, `contact-sheet.png`, 단계별 PNG·WebM·화면 스냅샷·실행 로그.
- `record.mjs`, `verify.mjs`, `assemble.mjs`: 촬영·검증·영상 연결 스크립트. 전용 로컬 fixture와 실행 환경이 필요하다. 비공개 테스트 계정·토큰은 `/tmp` fixture에 두며 Git에 추가하지 않는다.

검증 후 이번 촬영용 브라우저 3개·로컬 API·프론트·PG 대역과 테스트 MySQL·Temporal 컨테이너를 종료했다. 데이터와 촬영 증거는 보존했다. 양쪽 HEAD는 변경하지 않았으며 스테이징된 파일도 없다.
