# 반품 모바일·실제 Toss TEST 검증

> 이 문서는 해당 날짜·작업 범위의 검증 이력이다. 현재 구현·API 계약·PR 반영 구분·최종 영상·테스트 범위는 [2026-10-24 최신 안내](return-pickup-address-20261022.md)를 기준으로 한다. 과거 실제 Toss TEST 검증과 최신 PG 대역 검증을 합쳐 설명하지 않는다.

검증일: 2026-10-22. 프론트 `feat/commerce-web-ux-integration`의 미커밋 변경을 포함한 프로덕션 빌드와 백엔드 `feat/toss-full-refund`의 미커밋 변경을 사용했다. 커밋·푸시는 하지 않았다.

후속으로 주문 0건인 DB에서 실제 Commerce 주문 생성·Toss 승인·재고 확정·송장 등록·배송 완료를 새로 검증했다. 결과와 콜백 재진입·반품 주소 전역 배너 문제는 [신규 주문 전체 흐름 보고서](checkout-toss-delivery-verification-20261022.md)를 참고한다. 아래는 먼저 수행한 반품 검증의 범위를 기록한다.

## 모바일 검증

- Chromium에서 `isMobile: true`, `hasTouch: true`, 기본 390×844px로 구매자·판매자·관리자 화면을 조작했다. 실물 휴대전화 및 iOS Safari 검증은 아니다.
- 같은 흐름의 주요 화면 10개를 360·390·430px로 각각 확인했다. 총 30개 측정에서 문서의 가로 넘침과 열린 대화상자의 화면 밖 이탈이 없었다. 신청·확인 버튼은 내부 스크롤로 접근해 실제 실행했다.
- 반품 신청 → 반품지 등록 → 수거 접수 → 수거 완료 → 입고 → 옵션별 검수 → 재입고 → 관리자 환불 → 구매자 자동 완료 갱신을 통과했다.
- 네이비 2개·블랙 1개 검수에서 첫 상품만 저장했을 때는 견적을 조회하지 않았으며, 모든 상품 검수 후에만 환불 대기로 전환됐다.
- 재고는 네이비 100→102, 블랙 100→101이었다. 결제수단 환불액 23,000원, 복원 포인트 1,000P를 API 재조회로 확인했다.
- 구매자 화면은 수동 새로고침 0회·문서 재로딩 없이 완료 상태와 환불 합계를 반영했다.
- 이 모바일 전체 흐름의 PG HTTP 응답은 테스트 대역이었다. 실제 Toss 검증은 아래 별도 주문에서 수행했다.
- 구매자·관리자 브라우저 오류는 0건이었다. 판매자 미등록 반품지의 404는 정상적인 미등록 응답이지만, 후속 전체 주문 검증에서 콘솔 전역 오류 배너도 나타남을 확인했다. 이를 해결 완료로 판단하지 않는다.

## 실제 Toss TEST 검증

공식 개발 연동 체험 상점의 `test_gck_`·`test_gsk_` 키와 실제 `https://api.tosspayments.com`을 사용했다. 라이브 결제나 실제 청구는 없었다. 이 서버는 일반 API 실행 파일로 구동했으며, 이전 브라우저 테스트의 Toss HTTP 전송 가로채기를 사용하지 않았다.

### 실행 경계

1. 검증용 주문서에서 Commerce와 같은 Toss 결제위젯으로 카카오페이 인증을 진행했다. 인증은 사용자가 완료했다.
2. 임시 검증 프로그램이 현재 Go Toss 어댑터의 승인·조회 메서드를 호출했다. 제품 소스는 변경하지 않았다.
3. 승인 응답의 주문번호·금액·결제키·상태를 검증한 뒤, 새 합성 배송 완료 주문에 해당 승인 기록을 연결했다. 체크아웃 주문 생성·출고·배송 완료를 실제로 수행한 검증은 아니다.
4. 실제 반품 API로 신청·수거·입고·검수·재입고를 처리하고, 390px Commerce 관리자 화면에서 환불을 확정했다. 환불 확인창과 완료 화면은 360·390·430px에서도 확인했다.
5. 실제 Toss 재조회 및 로컬 DB 조회로 최종 상태와 거래 기록을 대조했다.

## 이번 검증에서 확인하지 않은 범위

- 실물 택배 접수·수거, 실기기·Safari, 라이브 결제, 가상계좌의 실제 은행 환불 입금, 현금영수증 발급은 포함하지 않았다.
- 승인부터 체크아웃·주문 워크플로우·배송까지 이어지는 전체 결제 흐름을 새로 검증한 것은 아니다. 현재 어댑터의 실제 승인·조회와 현재 반품 API·화면의 실제 취소·후처리를 확인했다.
- 쿠폰 미사용 주문을 사용했다. 최소 촬영 DB에 `coupon_targets`가 없어 로그인 후 상품 공개 쿠폰가 조회에서 서버 경고가 발생했다. 쿠폰 및 일반 체크아웃 생성의 통합 검증은 이번 결과에 포함하지 않는다.

실제 Toss 취소 응답 필드와 부분취소 방식은 [Toss 공식 결제 취소 가이드](https://docs.tosspayments.com/guides/v2/cancel-payment)를 기준으로 대조했다.
