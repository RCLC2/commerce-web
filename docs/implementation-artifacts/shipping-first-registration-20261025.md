# 신규 마켓 배송비 첫 등록 검증 (2026-10-25)

## 변경

- 미등록 배송비 조회는 `200 {success:true,data:null}`입니다. 0원 무료배송과 구분합니다.
- 판매자 홈에서 기본 배송비를 직접 선택해야 첫 저장이 가능합니다. 로딩·권한·서버 오류는 미등록으로 처리하지 않고 재조회할 수 있습니다.
- API는 첫 PUT으로 설정을 생성하며 이후 같은 마켓 행을 갱신합니다. 등록 전 주문 견적은 409로 차단합니다.

## 실제 화면·API·DB 검증

Docker MySQL 8.4와 실제 #201 API, #57 production build를 사용했습니다. 회원가입·로그인·신규 마켓 생성은 실제 API입니다. 판매자 역할, 상품 및 등록 전 장바구니 행은 격리된 로컬 테스트 DB의 fixture로 준비했습니다. PG 호출은 없습니다.

| 단계 | 확인 결과 |
| --- | --- |
| 실제 마켓 생성 | 201, 배송 설정 행 0개 |
| 미설정 조회 | 200, data:null |
| 등록 전 견적 | 409 RESOURCE_CONFLICT |
| 판매자 첫 등록 | 직접 3000원 선택, PUT200. 기본 배송비·회수비 3000원 저장 |
| 페이지 새로고침 | 저장한 3000원 유지 |
| 유료배송 견적 | 상품20000 + 배송3000 = 결제23000원 |
| 명시적 무료배송으로 변경 | 0원 저장·새로고침 유지. 견적 결제20000원 |
| 구매자의 설정 조회 | 403 |
| 모바일 | 390px에서 폼 너비 넘침 없음 |

주소록·환불·실물 수거·Toss 재결제 검증을 새로 수행한 결과로 확대하지 않습니다.

## 자동 회귀

- 배송 설정 API·컴포넌트 Vitest19건, TypeScript, 변경 파일 ESLint, production build 통과.
- #198·#201 실제 MySQL 배송 설정 테스트4건: 첫 등록/upsert, 기존 무료 반품비 보존, 명시적 무료 반품비 저장. SKIP없음.
- #200은 실제 main 커밋의 SQL79개로 만든 DB 업그레이드·데이터 보존, 빈 DB, 수거지 마이그레이션을 독립 DB3개에서 검증했습니다.
