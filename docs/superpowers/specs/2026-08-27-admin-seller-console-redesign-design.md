# 어드민·셀러 콘솔과 상품 카드 UX 재설계

- 날짜: 2026-08-27
- 상태: 대화에서 설계 승인 완료, 구현 전 문서 검토 대기
- 프론트 기준 브랜치: `feat/admin-seller-console-ui`
- 서버 기준 브랜치: `feat/admin-seller-console-api`
- 기준 리비전: 각 저장소의 최신 `origin/main`
- 커밋 정책: 사용자가 허락하기 전까지 설계와 구현 변경을 커밋하지 않는다.

## 1. 배경

현재 어드민·셀러 콘솔은 목록 API가 반환하는 데이터를 프론트에서 전부 모은 뒤 검색과 필터를 수행하는 화면이 많다. 일부 API는 서버에서 `limit`과 `offset`을 지원하지만 프론트가 모든 페이지를 순회하는 `collectAllUniquePages`를 사용해 서버 페이지네이션의 이점을 없앤다.

또한 다음 구조적 문제가 있다.

- 회원·마켓·주문 목록이 전체 데이터를 받은 뒤 브라우저에서 필터링된다.
- 어드민 마켓 목록은 마켓마다 페널티 API를 호출해 N+1 요청을 만든다.
- 상품·주문 목록 응답이 상세 엔티티를 그대로 재사용해 목록에 필요하지 않은 필드를 전송한다.
- 셀러 홈이 대시보드 외에도 상품·주문·재고 소스·정산 전체 목록을 추가로 조회한다.
- 셀러 리뷰 서비스가 리뷰별 상품 상세를 반복 조회한다.
- 공용 `DataTable`이 행마다 `auto-fit/minmax(150px, 1fr)` 그리드를 새로 계산해 열이 맞지 않고, 좁은 화면에서 필터와 작업 영역이 서로 침범한다.
- 광고 화면이 별도 사이드바 배열을 사용해 어드민 메뉴와 셀러 리뷰 메뉴가 누락된다.
- 셀러 상품 목록의 모든 행이 처음부터 수정 폼이라 조회와 편집 경계가 없다.
- 광고 목록의 `null`이 계약 오류로 취급되어 실제 장애가 아닌데도 전역 오류 배너가 나타난다.
- 사용자 홈 카테고리는 항상 5열이라 데스크톱에서도 불필요하게 2행이 된다.
- 상품 카드의 쿠폰 최적가가 별도 세로 블록이라 쿠폰이 없는 카드와 높이가 달라진다.

## 2. 목표

1. 고성장 목록은 서버 검색·필터·정렬·페이지네이션으로 전환한다.
2. 목록 DTO와 상세 DTO를 분리하고 각 화면에서 실제로 표시하는 필드만 응답한다.
3. 목록은 읽기 전용으로 만들고 행을 누르면 별도 상세 API로 모달을 연다.
4. 수정과 운영 작업은 상세 모달에서 명시적으로 수정 모드를 켠 뒤 수행한다.
5. 어드민과 셀러의 전체 사이드바를 한 정의에서 렌더링한다.
6. 데스크톱 표와 모바일 카드 레이아웃을 분리해 열 정렬과 반응형 동작을 안정화한다.
7. 빈 데이터와 실제 오류를 구분한다.
8. 사용자 홈 카테고리와 추천·PLP 가격 표시를 같은 카드 높이에 맞춘다.
9. 실제 백엔드 연결 E2E와 여러 뷰포트 스크린샷으로 레이아웃을 검증한다.

## 3. 비목표

- 고객용 PDP, 장바구니, 결제 흐름을 재설계하지 않는다.
- CMS의 소규모 고정 설정 목록까지 일률적으로 페이지네이션하지 않는다.
- 외부 재고 연동 프로토콜이나 정산 계산 공식을 변경하지 않는다.
- 신규 역할 체계나 권한 모델을 도입하지 않는다.
- 디자인 시스템 전체를 교체하지 않는다. 콘솔에서 필요한 공용 컴포넌트만 정리한다.
- 기존 사용자 체크아웃의 미추적 파일이나 다른 워크트리의 변경을 이동·수정하지 않는다.

## 4. 설계 원칙

### 4.1 목록과 상세 계약 분리

목록 API는 한 행을 그리는 데 필요한 요약 필드만 반환한다. 상세 모달을 열 때만 별도 상세 API를 호출한다. 상세 API는 해당 역할과 모달에 필요한 필드만 반환하며 데이터베이스 엔티티를 그대로 JSON으로 노출하지 않는다.

### 4.2 서버 주도 목록

검색·필터·정렬·페이지 경계는 서버에서 처리한다. 프론트는 응답의 `items`를 다시 필터링하지 않는다. 필터가 바뀌면 `page=1`로 돌아간다.

기본 페이지 응답은 다음 형태를 사용한다.

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0,
  "total_pages": 0,
  "summary": {}
}
```

`summary`는 화면 상단 요약 카드에 필요한 전체 필터 범위 집계가 있을 때만 사용한다. 현재 페이지 항목으로 전체 집계를 추정하지 않는다.

### 4.3 명시적 수정 모드

목록은 항상 읽기 전용이다. 상세 모달도 처음에는 읽기 모드이며 `수정` 버튼을 눌러야 입력 필드가 나타난다. 저장 실패 시 모달과 입력값을 유지한다.

### 4.4 빈 상태와 장애 분리

목록이 없으면 `[]`와 `total: 0`을 반환한다. `null`은 서버 프레젠테이션 계층에서 빈 컬렉션으로 정규화한다. 네트워크·권한·서버 오류만 오류 UI로 표시한다.

## 5. API 공통 계약

### 5.1 페이지 파라미터

- `page`: 1부터 시작하며 기본값은 1이다.
- `page_size`: 일반 목록 기본값 20, 셀러 주문 기본값 30, 감사 로그 기본값 50이다.
- 최대 `page_size`는 100이다.
- 잘못된 음수·0·상한 초과 값은 400으로 응답한다.
- 정렬은 각 엔드포인트가 허용한 값만 받으며 기본 정렬은 최신순이다.

### 5.2 날짜 파라미터

- `from`과 `to`는 `YYYY-MM-DD` 형식이다.
- 서버 시간대 경계는 서비스 기준 시간대인 `Asia/Seoul`로 해석한 뒤 저장소 시간대로 변환한다.
- `from > to`는 400으로 응답한다.

### 5.3 오류 응답

기존 전역 오류 포맷과 호환되는 구조를 유지하되 클라이언트가 구분할 수 있도록 HTTP 상태를 정확히 사용한다.

- 400: 잘못된 필터·페이지·상태 전이
- 401: 인증 없음
- 403: 역할 또는 마켓 소유권 부족
- 404: 상세 대상 없음
- 409: 현재 상태와 충돌하는 수정
- 500: 예상하지 못한 저장소·서버 오류

### 5.4 쿼리 구현

- 목록 쿼리는 필터가 적용된 `COUNT`와 제한된 `SELECT`를 수행한다.
- 목록 DTO에 필요한 조인은 한 번에 수행하거나 ID 집합으로 배치 조회한다.
- 행마다 상세 서비스나 저장소를 호출하지 않는다.
- 상세의 긴 하위 목록은 상세 응답에 무제한 포함하지 않고 별도 페이지 엔드포인트로 분리한다.

## 6. 어드민 API

### 6.1 회원

`GET /api/v1/admin/members`

- 필터: `q`, `role`, `status`, `page`, `page_size`
- `q`는 이메일과 화면에 표시 가능한 이름을 검색한다.
- 목록 필드: `id`, `email`, `display_name`, `role`, `status`, `notification_type`, `created_at`
- 요약: 전체·회원·셀러·어드민 수

`GET /api/v1/admin/members/:id`

- 상세 필드: 식별자, 이메일, 표시 이름, 연락처, 역할, 상태, 알림 설정, 마케팅 동의, 가입·수정 시각, 셀러 승인 상태
- 비밀번호 해시와 내부 인증 값은 포함하지 않는다.

`GET /api/v1/admin/members/:id/orders`

- 필터: `status`, `from`, `to`, `page`, `page_size`
- 주문 목록 DTO를 반환하며 회원 상세 모달의 주문 탭에서 사용한다.

기존 역할·상태 변경과 셀러 승인·반려 명령은 유지하되 상세 모달에서 호출한다.

### 6.2 마켓

`GET /api/v1/admin/markets`

- 필터: `q`, `status`, `page`, `page_size`
- 목록 필드: `id`, `name`, `profile_image_url`, `status`, `follower_count`, `tags`, `penalty_score`, `latest_penalty_at`
- 페널티 합계와 최근 시각은 목록 쿼리에서 집계해 프론트 N+1 요청을 제거한다.

`GET /api/v1/admin/markets/:id`

- 마켓 기본 정보와 운영 지표
- 셀러 요약: `id`, `email`, `display_name`, `status`
- 상품 수와 최대 7개의 `preview_products`
- 미리보기 상품 필드: `id`, `name`, `image_url`, `base_price`, `discount_price`, `status`
- 최근 페널티 이력은 제한된 요약만 포함한다.

`POST /api/v1/admin/markets/:id/penalties`

- 목록 행의 `페널티` 버튼으로 연 모달에서 호출한다.
- `reason`은 공백을 제외하고 필수이며 `score`는 허용 범위를 검증한다.

마켓 상세의 운영 상태 변경은 기존 상태 변경 명령을 사용한다. `더보기`는 프론트에서 고객용 `/markets/:id`를 새 탭으로 연다.

### 6.3 상품

`GET /api/v1/admin/products`

- 필터: `q`, `market_id`, `status`, `page`, `page_size`
- 목록 필드: 상품 ID·이름·대표 이미지, 마켓 ID·이름, 기준가·할인가, 판매 상태, 재고 요약, 운영 배지 요약

`GET /api/v1/admin/products/:id`

- 상세 필드: 마켓·카테고리 요약, 이미지, 옵션, 가격, 배송 유형, 판매 상태, 요약 설명, 운영 배지
- 고객 PDP 전용 추천·리뷰 전체 데이터는 포함하지 않는다.

어드민이 변경할 수 있는 범위는 운영 상태와 운영 배지로 제한한다. 셀러의 상품 콘텐츠와 옵션을 어드민 목록에서 즉시 편집하지 않는다.

### 6.4 주문

`GET /api/v1/admin/orders`

- 필터: `q`, `member_id`, `status`, `from`, `to`, `page`, `page_size`
- 목록 필드: 주문 코드·시각, 회원 요약, 대표 상품, 상품 수, 결제 금액, 주문 상태, 배송 상태

`GET /api/v1/admin/orders/:orderCode`

- 회원·수령인 요약, 주문 상품, 가격·할인·포인트·결제, 마켓 주문 상태, 배송 정보, 주소, 관리자 작업에 필요한 상태를 반환한다.
- 전체 엔티티를 그대로 반환하지 않는다.

강제 취소는 상세 모달 안에서 기존 명령을 호출하며 완료 후 목록과 상세 캐시를 함께 무효화한다.

### 6.5 정산

`GET /api/v1/admin/settlements`

- 필터: `q`, `market_id`, `target_month`, `status`, `page`, `page_size`
- 목록 필드: ID, 마켓 요약, 대상 월, 총매출, 수수료, 최종 지급액, 상태
- 요약: 필터 범위의 건수와 금액 합계

`GET /api/v1/admin/settlements/:id`

- 정산 기본 금액, 상태, 생성·확정·지급 시각, 마켓과 계좌 마스킹 요약을 반환한다.

`GET /api/v1/admin/settlements/:id/lines`

- 정산에 포함된 주문 항목을 별도로 페이지네이션한다.
- 상세 모달 안의 항목 탭에서 사용한다.

확정·지급 명령은 상세 모달에만 둔다.

### 6.6 광고·쿠폰·감사 로그

- 어드민 광고 캠페인은 서버 페이지네이션을 적용하고 필요 시 캠페인 상세을 별도 조회한다.
- 광고 가격표처럼 개수가 제한된 설정 목록은 페이지네이션하지 않는다.
- 쿠폰 정의와 감사 로그는 서버 페이지네이션으로 전환한다.
- 광고 캠페인·리포트 저장소 결과가 없으면 `[]`를 반환한다.

## 7. 셀러 API

### 7.1 대시보드

`GET /api/v1/seller/dashboard`

추가 전체 목록 호출 없이 홈을 그릴 수 있도록 다음을 한 번에 반환한다.

- 마켓 요약
- 주문·출고 대기·배송중·정산·재고 소스 지표 5개
- 처리 필요 작업
- 최근 주문 최대 5건의 목록 DTO
- 품절 임박 상품 최대 5건의 목록 DTO

집계는 제한된 쿼리와 `COUNT`를 사용하며 주문 100건을 읽어 메모리에서 계산하지 않는다.

### 7.2 상품

`GET /api/v1/seller/products`

- 필터: `q`, `status`, `shipping_type`, `page`, `page_size`
- 목록 필드: ID·이름·이미지, 카테고리 요약, 현재 가격, 재고 요약, 배송 유형, 판매 상태, 수정 시각
- 설명 HTML과 전체 옵션은 포함하지 않는다.

`GET /api/v1/seller/products/:id`

- 소유권을 확인한 뒤 이미지, 가격, 옵션, 배송 유형, 설명 문서와 편집에 필요한 필드를 반환한다.

생성·수정 명령은 기존 상품 명령을 사용하되 소유권 검증을 유지한다. HTML 콘텐츠 편집기는 상세·등록 모달의 전용 화면에서 값을 편집하고 저장 명령에 포함한다.

### 7.3 주문·배송

`GET /api/v1/seller/orders`

- 기본 `page_size=30`
- 필터: `q`, `status`, `from`, `to`, `page`, `page_size`
- 목록 필드: 주문 코드·시각, 대표 상품과 수량, 결제 금액, 주문·배송 상태

`GET /api/v1/seller/orders/:orderCode`

- 요청 마켓에 속한 상품만 노출하며 주문 상품, 배송, 수령인, 송장 작업에 필요한 필드를 반환한다.

송장 등록·배송 시작·배송 완료 명령은 상세 모달에서 실행한다.

### 7.4 정산

`GET /api/v1/seller/settlements`

- 필터: `target_month`, `status`, `page`, `page_size`
- 목록 DTO와 필터 범위 요약 금액을 반환한다.

`GET /api/v1/seller/settlements/:id`와 `/lines`

- 마켓 소유권을 검증한다.
- 정산 상세와 주문별 정산 항목 페이지를 분리한다.

### 7.5 리뷰

`GET /api/v1/seller/reviews`

- 필터: `q`, `rating`, `status`, `from`, `to`, `page`, `page_size`
- 목록 필드: 리뷰 ID, 상품 요약, 평점, 본문 미리보기, 이미지 수, 상태, 작성 시각
- 상품 요약은 조인 또는 배치 조회해 리뷰별 상품 상세 N+1을 제거한다.

`GET /api/v1/seller/reviews/:id`

- 전체 본문·이미지, 상품·옵션 요약, 주문 코드를 반환한다.
- 요청 마켓 상품에 작성된 리뷰인지 검증한다.

### 7.6 광고

- 캠페인 목록과 성과 목록을 페이지 응답으로 정리한다.
- 캠페인 생성은 명령 API를 유지하고 프론트 생성 모달에서 호출한다.
- 결과가 없을 때 캠페인·리포트·상품 선택 목록은 빈 배열로 응답한다.

## 8. 프론트 구조

### 8.1 공용 탐색

어드민과 셀러 링크 정의를 광고 콘솔 밖의 공용 모듈로 옮긴다. 모든 어드민 페이지는 같은 `adminLinks`, 모든 셀러 페이지는 같은 `sellerLinks`를 사용한다. 활성 상태는 현재 경로가 링크 경로와 같거나 해당 하위 경로일 때 적용한다.

### 8.2 공용 목록 컴포넌트

기존 행별 자동 그리드 `DataTable`을 다음 구조로 대체한다.

- 데스크톱: 의미 있는 `<table>`과 열별 너비·정렬 규칙
- 모바일: 같은 데이터를 카드 목록으로 렌더링
- 표 컨테이너만 가로 스크롤을 허용하고 페이지 전체 오버플로를 금지
- 행 클릭과 행 내부 작업 버튼을 구분하며 작업 버튼은 행 클릭 이벤트를 전파하지 않음
- 빈 상태, 로딩 스켈레톤, 영역 오류 상태를 공통 제공

### 8.3 공용 필터와 페이지네이션

- 검색 입력은 짧게 디바운스한다.
- 필터 변경 시 페이지를 1로 초기화한다.
- React Query 키에 모든 필터·정렬·페이지 값을 포함한다.
- 페이지 이동 중 이전 데이터를 유지해 레이아웃 점프를 줄인다.
- 응답 총 페이지가 줄어 현재 페이지가 범위를 벗어나면 마지막 유효 페이지로 이동한다.

### 8.4 공용 모달

- 접근 가능한 제목과 설명을 제공한다.
- 열릴 때 포커스를 이동하고 닫힐 때 원래 행 또는 버튼으로 돌려보낸다.
- `Escape`, 배경 클릭, 닫기 버튼을 지원하되 저장 중에는 우발적 닫기를 방지한다.
- 본문만 스크롤하고 헤더와 하단 작업 버튼은 고정한다.
- 모바일에서는 화면 높이에 맞는 전체 폭 패널로 전환한다.
- 상세 로딩 실패는 모달 내부에서 재시도한다.

상품 HTML 편집은 중첩 모달을 띄우지 않는다. 같은 상품 모달을 전체 크기 편집 화면으로 전환하고 `돌아가기`로 이전 폼 상태를 복원한다.

## 9. 화면 상호작용

### 9.1 어드민

- 회원 행을 누르면 기본 정보와 주문 내역 탭이 있는 상세 모달을 연다.
- 마켓 행은 상세 모달, `페널티` 버튼은 사유·점수 전용 모달을 연다. 기존 전체 마켓 드롭다운과 무의미한 `선택` 버튼은 제거한다.
- 마켓 상품 미리보기는 데스크톱에서 한 줄 최대 7개, 좁은 화면에서 가로 스크롤로 유지한다.
- 상품·주문·정산 행을 누르면 각 상세 모달을 연다. 목록에는 입력 필드를 두지 않는다.
- 주문 취소와 정산 지급 같은 위험 작업은 대상과 결과를 확인할 수 있는 상세 모달에서 수행한다.

### 9.2 셀러

- 홈 지표 5개는 넓은 화면에서 한 줄이고 좁은 화면에서만 줄바꿈한다.
- 최근 주문은 최대 5개와 `더보기`만 표시한다.
- 상품 페이지 상단은 조회 목록과 `상품 등록` 버튼으로 구성한다. 생성 폼은 모달에서 연다.
- 상품 목록은 읽기 전용이며 상세 모달의 `수정` 버튼 이후에만 필드가 나타난다.
- 광고 캠페인 생성 폼은 페이지 본문에서 제거하고 버튼으로 모달을 연다.
- 주문 목록에는 송장 입력을 노출하지 않고 상세 모달로 이동한다.
- 리뷰 메뉴는 어떤 셀러 하위 페이지에서도 항상 보이고, 리뷰 행을 누르면 상품·옵션·주문 정보를 포함한 상세 모달을 연다.

## 10. 사용자 홈과 상품 가격

### 10.1 홈 카테고리

현재 고정 5열을 자동 맞춤 그리드로 변경한다. 각 칩은 읽을 수 있는 최소 너비를 갖고, 현재 항목이 컨테이너에 들어가면 한 줄로 표시한다. 화면이 좁거나 카테고리가 늘어 최소 너비를 지킬 수 없을 때만 다음 줄로 넘어간다.

### 10.2 추천·PLP 가격

공용 상품 카드 가격을 한 줄 컴포넌트로 분리한다. 표시 우선순위는 쿠폰 최적가, 자체 할인가, 일반 판매가 순이다.

- 쿠폰 가능: 현재 판매가를 취소선으로 표시하고 오른쪽에 `쿠폰 최적가 {가격}`을 표시한다.
- 자체 할인만 있음: 기준 판매가를 취소선으로 표시하고 오른쪽에 할인가를 표시한다.
- 할인 없음: 일반 판매가만 강조한다.

쿠폰 여부에 따라 별도 세로 블록을 추가하지 않는다. 추천 상품과 PLP는 같은 컴포넌트를 사용해 상품명 아래 가격 영역 높이를 맞춘다.

## 11. 오류와 캐시 처리

- 목록 조회 실패는 해당 목록 영역만 오류 상태로 바꾸고 정상적인 다른 쿼리 결과는 유지한다.
- 전역 콘솔 레이아웃이 선택적 보조 쿼리 하나의 실패 때문에 전체 페이지를 오류로 덮지 않게 한다.
- 빈 광고 데이터는 정상 빈 상태로 표시한다.
- 상세 모달을 닫을 때 오래된 상세 응답이 다음 대상에 표시되지 않게 쿼리 키를 대상 ID로 분리한다.
- 수정 성공 시 목록·상세·관련 대시보드 캐시를 필요한 범위에서 무효화한다.
- 수정 실패 시 사용자의 입력과 모달 상태를 유지하고 필드 또는 모달 하단에 오류를 표시한다.

## 12. 보안과 개인정보

- 모든 상세 API는 서버에서 역할과 마켓 소유권을 검증한다.
- 회원·주문 상세는 화면에 필요한 개인정보만 반환한다.
- 계좌·결제 식별자는 마스킹하거나 운영에 필요한 최소 값만 노출한다.
- 상품 HTML 미리보기는 현재의 샌드박스 격리를 유지한다.
- 새 탭 링크에는 `noopener,noreferrer`를 적용한다.

## 13. 테스트 전략

### 13.1 서버

- 핸들러 테스트: 기본값, 잘못된 페이지·날짜, 필터 전달, 빈 배열, 상태 코드
- 저장소·서비스 테스트: 필터 조합, 정렬, 전체 개수, 페이지 경계, DTO 필드
- 권한 테스트: 다른 셀러의 상품·주문·정산·리뷰 상세 차단
- 회귀 테스트: 마켓 상품 미리보기 7개 제한, 페널티 집계, 리뷰 상품 배치 조회
- 계약 테스트: 목록 응답에 상세 전용 필드가 없고 상세 응답에 내부 필드가 없는지 검증

### 13.2 프론트

- API 스키마 테스트: 페이지 응답과 각 목록·상세 DTO
- 쿼리 테스트: 필터·페이지가 URL과 요청에 반영되고 필터 변경 시 첫 페이지로 이동
- 컴포넌트 테스트: 읽기/수정 모드, 모달 포커스, 빈 상태, 페이지 버튼
- 탐색 테스트: 광고 페이지에서도 전체 어드민·셀러 메뉴와 리뷰 메뉴 노출
- 상품 가격 테스트: 일반·자체 할인·쿠폰 최적가의 한 줄 표시
- 카테고리 테스트: 충분한 폭의 한 줄과 좁은 폭의 자동 줄바꿈

### 13.3 E2E와 시각 검증

- 실제 백엔드와 시드 데이터를 연결해 어드민·셀러 전체 대상 페이지를 검증한다.
- 회원·마켓·상품·주문·정산·리뷰 상세 모달을 열고 핵심 정보를 확인한다.
- 회원 수정, 페널티 등록, 상품 수정, 주문 배송 작업, 광고 캠페인 생성을 검증한다.
- 1440x900, 1024x768, 390x844 뷰포트에서 주요 페이지 스크린샷을 저장한다.
- 페이지 전체 가로 오버플로, 필터 겹침, 표 열 정렬, 모달 잘림, 버튼 침범을 확인한다.
- 브라우저 플러그인 연결이 Windows ACL 문제로 계속 불가능하면 저장소의 Playwright E2E가 생성한 스크린샷을 사용하고 원인을 기록한다.

최종 명령은 다음 범위를 포함한다.

- 서버: 전체 Go 테스트와 포맷·정적 검사
- 프론트: 단위 테스트, lint, production build
- 통합: 실제 백엔드 기반 콘솔 E2E와 스크린샷 검증

## 15. 완료 기준

- 대상 목록이 전체 페이지를 자동 수집하거나 프론트에서 필터링하지 않는다.
- 회원·마켓·상품·주문·정산·리뷰가 목록과 상세 API를 구분한다.
- 회원 상세 수정과 주문 탭이 작동한다.
- 마켓 행별 페널티 모달, 셀러 상세, 상품 7개 미리보기, 새 탭 더보기가 작동한다.
- 어드민 상품·주문·정산 목록은 읽기 전용이고 상세 모달에서 운영 작업을 수행한다.
- 광고 페이지를 포함한 모든 콘솔 페이지의 사이드바가 동일하다.
- 셀러 홈 지표가 넓은 화면에서 한 줄이고 최근 주문이 5개를 넘지 않는다.
- 셀러 상품 등록·상세·수정·HTML 편집 흐름이 분리된다.
- 셀러 광고 빈 데이터는 오류가 아니며 생성 폼이 모달로 열린다.
- 셀러 주문 기본 페이지 크기가 30이고 날짜·상태 서버 필터가 작동한다.
- 셀러 리뷰 상세에서 상품·옵션·주문 정보를 확인할 수 있다.
- 사용자 홈 카테고리가 가능한 경우 한 줄이며 필요할 때만 줄바꿈한다.
- 추천·PLP 상품 가격이 단일 가로 행으로 정렬된다.
- 목표 뷰포트 스크린샷에서 영역 침범과 의도하지 않은 페이지 가로 스크롤이 없다.
- 요청된 테스트가 통과하고 두 저장소 모두 사용자 승인 전 커밋이 없다.
