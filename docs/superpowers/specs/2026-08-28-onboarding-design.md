# 신규 회원 추천 취향 온보딩 설계

## 요약

신규 고객 회원이 가입을 마치면 자동 로그인한 뒤 상품 10개를 O/X로 평가하는 선택형 온보딩으로 이동한다. 사용자는 카드를 오른쪽 또는 왼쪽으로 스와이프하거나, 화면 버튼 또는 키보드로 응답한다. 온보딩 응답은 기존 클릭·찜·좋아요·구매 기반 추천의 콜드 스타트 신호로 사용하며 실제 쇼핑 행동이 쌓일수록 영향력을 줄인다.

온보딩은 쇼핑 진입을 막지 않는다. 사용자는 시작 전이나 진행 중 언제든 건너뛸 수 있고, 이미 평가한 응답은 보존된다. 저장 또는 추천 생성이 실패해도 인기 상품 fallback을 제공한다.

## 배경

현재 프론트엔드는 `src/components/register-page.tsx`에서 회원가입 성공 후 `/login`으로 이동한다. 회원가입 응답 스키마는 회원 ID만 사용하고, 액세스 토큰은 로그인 API에서만 받는다.

서버 추천기는 최근 30일의 클릭, 찜, 좋아요, 구매를 합산해 사용자 프로필과 추천 결과를 배치 생성한다. 새 회원에게는 행동 이력이 없어 인기 상품 fallback만 제공한다. 신규 온보딩은 이 콜드 스타트 구간에 명시적 취향 신호를 공급한다.

## 목표

- 가입 성공 후 로그인 화면을 거치지 않고 취향 온보딩으로 연결한다.
- 카테고리·마켓·가격대가 균형 잡힌 상품 10개로 초기 선호를 수집한다.
- O는 강한 긍정, X는 약한 부정으로 반영해 과도한 부정 추론을 피한다.
- 새로고침, 네트워크 오류, 다른 기기 로그인을 거쳐도 진행 상태를 복구한다.
- 완료 또는 건너뛰기 직후 개인화 추천을 생성한다.
- 온보딩 장애가 회원가입 성공이나 쇼핑 진입을 막지 않게 한다.
- 스와이프 외에 버튼과 키보드를 제공해 입력 방식과 접근성을 보장한다.

## 범위 밖

- 세션 중 앞선 응답에 따라 다음 상품을 바꾸는 적응형 문항 구성
- 자연어 취향 조사, 브랜드 설문, 사이즈 또는 신체 정보 수집
- 기존 회원에게 온보딩을 소급 강제 노출하는 작업
- 관리자용 후보 상품 수동 큐레이션 도구
- v1에서의 추천 모델 학습 또는 협업 필터링 교체

## 사용자 흐름

### 가입 직후

1. 고객이 회원가입 양식을 제출한다.
2. 서버가 기능 노출 대상으로 선정된 회원에게 `NOT_STARTED` 온보딩 세션을 생성하고 액세스 토큰을 함께 반환한다.
3. 프론트엔드는 기존 인증 토큰 저장소에 토큰을 저장한다.
4. 프론트엔드는 `/onboarding/preferences`로 이동한다.
5. 페이지는 세션에 고정된 상품 10개와 기존 응답을 조회한다.
6. 사용자는 각 상품을 O 또는 X로 평가한다.
7. 10개가 모두 평가되면 완료 요청을 보내고 홈으로 이동한다.

가입 자체는 온보딩 세션 생성 실패 때문에 롤백하지 않는다. 세션을 만들 수 없으면 회원가입 응답의 온보딩 상태를 `UNAVAILABLE`로 반환하고 홈으로 이동시킨다. 서버는 오류를 기록하고 사용자는 인기 상품 추천을 받는다.

기능 플래그가 꺼져 있거나 rollout 대상이 아닌 신규 회원은 `NOT_ELIGIBLE`이며 토큰 확장 필드를 받지 않는다. 이 회원은 기존과 같이 가입 후 로그인 화면으로 이동한다. 따라서 단계적 출시가 비대상 회원의 인증 흐름을 바꾸지 않는다.

### 중단과 재개

- `IN_PROGRESS` 세션이 있는 회원은 다음 로그인 후 온보딩을 이어서 진행한다.
- 로그인 성공 후 프론트엔드는 토큰을 저장하고 세션 조회 API를 한 번 호출한다. 응답이 `IN_PROGRESS`일 때만 온보딩으로 이동하고 그 외에는 원래 목적지 또는 홈으로 이동한다.
- 완료 또는 건너뛰기 상태는 자동으로 다시 노출하지 않는다.
- 기존 회원처럼 온보딩 세션이 없는 계정은 `NOT_ELIGIBLE`로 취급한다.
- 마이페이지의 `취향 다시 설정`은 새 generation의 세션을 생성한다. 이전 세션은 감사와 분석을 위해 보존한다.

### 건너뛰기

- 상단 우측에 항상 `건너뛰기`를 표시한다.
- 평가 전 건너뛰면 인기 상품 fallback으로 이동한다.
- 일부 평가 후 건너뛰면 저장된 응답만 초기 추천 신호로 반영한다.
- 건너뛰기 요청이 실패해도 `나중에 할게요`로 홈에 진입할 수 있다. 서버 상태는 다음 인증 세션에서 다시 동기화한다.

## 화면 및 상호작용

```text
취향 찾기  3/10                                  건너뛰기
┌───────────────────────────────────────────────┐
│                                               │
│                 상품 이미지 4:5               │
│                                               │
│       X 별로예요                 O 좋아요      │
├───────────────────────────────────────────────┤
│ 마켓명                                        │
│ 상품명                                        │
│ 판매가                                        │
└───────────────────────────────────────────────┘
            [ X 별로예요 ]  [ O 좋아요 ]
                    방금 선택 취소
```

### 동작 규칙

- 오른쪽 스와이프, O 버튼, 키보드 오른쪽 방향키는 `LIKE`다.
- 왼쪽 스와이프, X 버튼, 키보드 왼쪽 방향키는 `DISLIKE`다.
- 카드 너비의 25% 이상 이동하거나 충분한 속도의 fling이 감지되면 선택을 확정한다.
- 임계값에 못 미치면 카드는 원위치로 복귀한다.
- 드래그 방향에 따라 카드 위에 O 또는 X 스탬프와 색상 피드백을 표시한다.
- 직전 응답 한 건만 실행 취소할 수 있다. 실행 취소는 서버 응답 삭제 후 이전 카드로 돌아간다.
- 진행률은 서버에 저장된 응답 수가 아니라 현재 클라이언트의 최신 응답 상태를 즉시 반영한다.
- 첫 카드에는 `오른쪽은 좋아요, 왼쪽은 별로예요` 안내를 한 번만 노출한다. 별도 설명 화면은 두지 않는다.
- 마지막 응답 후 저장 큐를 비우고 `취향을 반영했어요`를 짧게 표시한 다음 홈으로 이동한다.

### 접근성

- O/X 버튼은 최소 44px 터치 영역과 명시적인 접근성 이름을 갖는다.
- 카드 변화와 `n/10`, 저장 실패, 완료 상태를 라이브 영역으로 알린다.
- 포커스는 응답 후 다음 카드의 제목 또는 O 버튼으로 예측 가능하게 이동한다.
- `prefers-reduced-motion`에서는 카드 회전과 fling 애니메이션을 짧은 fade 전환으로 대체한다.
- O와 X를 색상만으로 구분하지 않고 텍스트와 아이콘을 함께 사용한다.

## 후보 상품 선정

v1은 적응형 문항 대신 서버가 한 번 선정한 균형 표본 10개를 사용한다. 세션의 상품과 순서는 저장되며 새로고침이나 기기 변경으로 바뀌지 않는다.

### 자격 조건

- 상태가 `SELLING`이며 삭제되지 않은 상품
- 실제 판매 가능한 재고가 있는 상품
- 대표 이미지가 있는 상품
- 광고 또는 스폰서 노출이 아닌 일반 상품

### 선정 절차

1. 인기 점수와 최근 등록일을 혼합해 최대 200개의 후보 풀을 만든다.
2. 후보 풀의 가격 분포를 저가·중가·고가 3분위로 나눈다.
3. 최상위 카테고리, 마켓, 가격 구간별로 후보를 그룹화한다.
4. 동일 상위 카테고리는 최대 2개, 동일 마켓은 최대 1개를 우선 제약으로 적용한다.
5. 세 가격 구간이 모두 포함되도록 선택한다.
6. `member_id`, `session_id`, `candidate_version`의 해시를 seed로 사용해 결정적으로 순서를 섞는다.
7. 10개를 채우지 못하면 동일 마켓 제한, 가격 구간 제한, 카테고리 제한 순으로 완화한다. 상품 중복은 허용하지 않는다.

후보 자격을 만족하는 전체 상품이 10개보다 적으면 가능한 상품만 제공하고 `total_count`를 실제 개수로 반환한다. 자격 상품이 5개보다 적으면 온보딩을 `UNAVAILABLE`로 종료하고 인기 상품 fallback을 사용한다.

### 판매 상태 변경

- 아직 평가하지 않은 상품이 재조회 시 판매 불가 상태면 동일 위치에 대체 상품을 배정한다.
- 이미 평가한 상품은 세션 기록을 유지하되 추천 후보에서는 제외한다.
- 클라이언트에 노출된 직후 판매 상태가 바뀐 상품의 응답은 취향 신호로 수락하되 구매 가능한 추천 결과에는 포함하지 않는다.

## 상태 모델

상태는 다음과 같이 이동한다.

```text
NOT_STARTED ──첫 후보 조회──> IN_PROGRESS ──모두 응답──> COMPLETED
     │                             │
     └────────건너뛰기─────────────┴──────────────> SKIPPED

세션 없음 -> NOT_ELIGIBLE
세션 생성 또는 후보 부족 -> UNAVAILABLE
```

- `COMPLETED`는 `responded_count == total_count`일 때만 허용한다.
- `SKIPPED`는 응답 수와 관계없이 허용한다.
- 종료된 세션의 응답은 변경하지 않는다.
- 취향 다시 설정은 기존 세션을 되돌리지 않고 generation을 증가시킨 새 세션을 만든다.

## API 계약

모든 온보딩 API는 인증된 현재 회원에게만 허용한다. 다른 회원의 session ID를 입력으로 받지 않는다.

### 회원가입 응답 확장

`POST /api/v1/auth/signup`

```json
{
  "id": 123,
  "email": "user@example.com",
  "type": "MEMBER",
  "role": "MEMBER",
  "status": "ACTIVE",
  "accessToken": "...",
  "tokenType": "Bearer",
  "expiresIn": 3600,
  "onboardingStatus": "NOT_STARTED"
}
```

기존 `id`, `email`, `type`, `role`, `status` 필드를 유지하면서 로그인 응답과 동일한 토큰 필드를 추가한다. 신규 프론트엔드는 확장 스키마를 사용하고, 알 수 없는 필드를 무시하는 기존 클라이언트는 계속 동작한다.

위 예시는 rollout 대상의 성공 응답이다. `NOT_ELIGIBLE` 응답은 기존 회원 필드와 `onboardingStatus`만 반환하며 토큰 필드는 생략한다. rollout 대상으로 선정됐지만 세션 생성이 실패한 `UNAVAILABLE` 응답은 사용자가 로그인 화면에 갇히지 않도록 토큰 필드를 반환하고 홈 fallback을 허용한다.

### 세션 조회 또는 시작

`GET /api/v1/me/onboarding`

```json
{
  "session_id": 9001,
  "status": "IN_PROGRESS",
  "candidate_version": "balanced_v1",
  "total_count": 10,
  "responded_count": 2,
  "items": [
    {
      "position": 1,
      "choice": "LIKE",
      "product": {
        "id": 51,
        "market_id": 8,
        "market_name": "마켓명",
        "name": "상품명",
        "image_url": "https://example.invalid/product.jpg",
        "base_price": 30000,
        "discount_price": 25000
      }
    }
  ]
}
```

`NOT_STARTED` 세션은 이 요청에서 후보를 선정한 뒤 `IN_PROGRESS`가 된다. 동일 세션에 대한 반복 조회는 동일한 후보와 순서를 반환한다.

### 응답 저장

`PUT /api/v1/me/onboarding/responses/{productId}`

```json
{
  "choice": "LIKE",
  "input_method": "SWIPE"
}
```

- `choice`: `LIKE | DISLIKE`
- `input_method`: `SWIPE | BUTTON | KEYBOARD`
- 동일 상품에 대한 반복 요청은 최신 값으로 upsert한다.
- 클라이언트는 세션 단위 직렬 큐로 요청 순서를 보장한다.
- 응답 상품이 현재 세션에 없거나 세션이 종료되었으면 `409 Conflict`를 반환한다.

### 응답 취소

`DELETE /api/v1/me/onboarding/responses/{productId}`

현재 활성 세션의 응답만 삭제한다. 이미 없는 응답의 삭제도 성공으로 처리해 멱등성을 보장한다.

### 완료 또는 건너뛰기

`POST /api/v1/me/onboarding/finish`

```json
{
  "status": "COMPLETED"
}
```

응답:

```json
{
  "status": "COMPLETED",
  "responded_count": 10,
  "recommendation_ready": true
}
```

종료 상태와 응답은 먼저 커밋한다. 개인 추천 생성이 실패하면 `recommendation_ready`를 `false`로 반환하고 기존 Temporal 추천 워크플로에 회원 단위 재생성 작업을 제출한다. 홈은 준비될 때까지 인기 상품 fallback을 사용한다. 같은 종료 요청을 반복해도 같은 종료 상태를 반환한다.

### 취향 다시 설정

`POST /api/v1/me/onboarding/restart`

종료된 최신 세션이 있을 때만 generation을 증가시킨 `NOT_STARTED` 세션을 만든다. 이미 활성 세션이 있으면 그 세션을 반환한다.

### best-effort 화면 이벤트

`POST /api/v1/me/onboarding/events`

```json
{
  "event": "onboarding_product_impression",
  "product_id": 51,
  "position": 3
}
```

서버의 상태 변경 API에서 알 수 없는 `viewed`, `product_impression`, `resumed`, `save_failed` 화면 이벤트만 받는다. 이벤트 이름은 allow-list로 제한하고 product가 현재 세션 item인지 검증한다. 저장 실패가 사용자 흐름을 막지 않도록 클라이언트는 이 API를 best-effort로 호출하며 실패를 재전파하지 않는다. rated, undo, skipped, completed는 해당 상태 변경 API가 서버에서 직접 기록한다.

## 데이터 모델

### `onboarding_sessions`

| 컬럼 | 타입 | 규칙 |
|---|---|---|
| `id` | BIGINT | 기본 키 |
| `member_id` | BIGINT | 회원 식별자, 인덱스 |
| `generation` | INTEGER | 회원별 1부터 증가 |
| `status` | VARCHAR(30) | 상태 모델의 서버 상태 |
| `candidate_version` | VARCHAR(50) | 기본값 `balanced_v1` |
| `total_count` | INTEGER | 기본값 10 |
| `responded_count` | INTEGER | 기본값 0 |
| `started_at` | TIMESTAMP NULL | 후보 최초 조회 시각 |
| `finished_at` | TIMESTAMP NULL | 완료 또는 건너뛰기 시각 |
| `created_at` | TIMESTAMP | 생성 시각 |
| `updated_at` | TIMESTAMP | 수정 시각 |

제약:

- `UNIQUE(member_id, generation)`
- `INDEX(member_id, status)`
- 한 회원의 활성 세션은 서비스 트랜잭션과 잠금으로 하나만 허용한다.

### `onboarding_items`

| 컬럼 | 타입 | 규칙 |
|---|---|---|
| `id` | BIGINT | 기본 키 |
| `session_id` | BIGINT | 세션 식별자 |
| `product_id` | BIGINT | 노출 상품 |
| `position` | INTEGER | 1부터 시작하는 노출 순서 |
| `choice` | VARCHAR(20) NULL | `LIKE | DISLIKE` |
| `input_method` | VARCHAR(20) NULL | 입력 방식 |
| `responded_at` | TIMESTAMP NULL | 최신 응답 시각 |
| `created_at` | TIMESTAMP | 생성 시각 |
| `updated_at` | TIMESTAMP | 수정 시각 |

제약:

- `UNIQUE(session_id, product_id)`
- `UNIQUE(session_id, position)`
- `INDEX(session_id, choice)`

`responded_count`는 빠른 상태 응답을 위한 파생 캐시다. 응답 upsert와 삭제 트랜잭션에서 원자적으로 갱신하며, 완료 시 실제 item 수와 일치하는지 다시 검증한다.

## 추천 신호 통합

온보딩 응답은 기존 행동 신호 조회에 새로운 source로 합쳐진다.

| 신호 | 기본 가중치 |
|---|---:|
| 상품 클릭 | `+1.0` |
| 온보딩 O | `+3.0` |
| 좋아요 | `+3.0` |
| 찜 | `+4.0` |
| 구매 확정 | `+8.0` |
| 온보딩 X | `-0.5` |

### 감쇠

온보딩 신호의 최종 계수는 다음과 같다.

```text
age_decay = max(0, 1 - 세션 finished_at 후 경과일 / 90)
behavior_decay = max(0, 1 - 온보딩 이후 실제 행동 수 / 20)
effective_weight = base_weight × age_decay × behavior_decay
```

90일이 지나거나 온보딩 이후 실제 행동이 20개 쌓이면 초기 신호는 추천 점수에 더 이상 영향을 주지 않는다. 세션 기록 자체는 분석을 위해 보존한다.

추천에는 최신으로 종료된 generation 한 개의 응답만 사용한다. 취향 다시 설정 세션이 진행 중인 동안에는 직전 종료 세션의 신호를 유지하고, 새 세션이 `COMPLETED` 또는 `SKIPPED`로 종료되면 이전 generation의 신호를 대체한다. 진행 중 세션의 일부 응답은 추천에 사용하지 않는다.

### 특성 반영

- O는 상품 카테고리, 마켓, 태그, 가격대의 긍정 affinity를 높인다.
- X는 카테고리, 마켓, 태그의 부정 affinity만 높이고 가격대에는 반영하지 않는다.
- 온보딩에 노출된 상품은 O/X와 관계없이 최초 추천 결과에서 제외한다.
- 부정 affinity의 최종 감점은 감점 전 점수의 30%를 넘지 않는다.
- O와 실제 긍정 행동이 하나도 없으면 X만으로 취향을 단정하지 않고, 평가 상품을 제외한 인기 상품 fallback을 반환한다.

### 즉시 갱신

`finish`는 현재 회원만 대상으로 기존 프로필 생성과 후보 500개 scoring을 동기 실행한다. 결과는 기존 `recommendation_user_profiles`와 `recommendation_results`에 같은 알고리즘 버전으로 저장한다. 실패하면 종료 상태를 되돌리지 않고 회원 단위 Temporal 재시도를 시작한다.

## 클라이언트 상태와 오류 처리

클라이언트는 서버 세션을 진실의 원천으로 삼고 화면 응답은 낙관적으로 반영한다. PUT과 DELETE는 하나의 직렬 큐에서 실행해 재선택과 실행 취소의 순서가 뒤바뀌지 않게 한다.

- 후보 조회 실패: `다시 시도`와 `나중에 할게요`를 제공한다.
- 응답 저장 실패: 최신 상품 선택을 큐에 남기고 지수 backoff로 재시도한다. 상단에 `저장 중` 또는 `저장에 실패했어요`를 표시한다.
- 종료 전: 큐가 빌 때까지 기다리되 5초를 넘기면 재시도 화면과 홈 이동을 함께 제공한다.
- 종료 실패: 현재 카드와 응답을 유지한다.
- 추천 생성 실패: 완료 상태는 유지하고 홈에서 인기 상품을 제공한다.
- 브라우저 종료: 이미 성공한 응답은 서버에서 복구한다. 전송되지 않은 마지막 낙관적 응답은 다시 평가할 수 있다.
- 인증 만료: 현재 경로를 보존해 로그인 후 같은 세션으로 돌아온다.

선택형 기능이므로 오류 화면에는 항상 쇼핑으로 이동할 수 있는 경로가 있어야 한다.

## 분석 이벤트

| 이벤트 | 주요 속성 |
|---|---|
| `onboarding_viewed` | session, candidate version, total count |
| `onboarding_product_impression` | product, position |
| `onboarding_rated` | product, position, choice, input method |
| `onboarding_undo` | product, position |
| `onboarding_skipped` | responded count, elapsed time |
| `onboarding_completed` | O/X 수, elapsed time |
| `onboarding_resumed` | responded count |
| `onboarding_save_failed` | operation, HTTP status, retry count |

이벤트에는 이메일, 토큰, 비밀번호, 자유 입력 정보가 포함되지 않는다. session과 member 식별자는 분석 시스템의 기존 가명화 정책을 따른다.

## 성공 지표

- 온보딩 진입 대비 완료율
- 건너뛰기율과 건너뛰기 위치
- 중앙 평가 완료 시간
- O/X 비율과 전부 X인 세션 비율
- 인기 상품 fallback 집단 대비 D1·D7 추천 클릭률
- 추천을 통한 찜과 구매 전환율
- 기존 대비 회원가입 완료율 비열화 여부
- 후보 조회·응답 저장·종료 API 오류율

## 성능 목표

- 응답 저장 API 서버 처리 p95 300ms 이하
- 세션 조회 API 서버 처리 p95 500ms 이하
- 카드 드래그와 전환은 지원 기기에서 60fps를 목표로 한다.
- 완료 API는 동기 추천 생성 포함 p95 1초 이하를 목표로 한다. 초과 또는 실패 시 추천 비준비 응답과 fallback을 사용한다.

## 보안과 무결성

- 모든 `/me/onboarding` API는 인증 미들웨어 뒤에 둔다.
- member ID는 토큰 컨텍스트에서만 가져오며 요청 body나 path로 받지 않는다.
- 응답 상품이 현재 활성 세션에 속하는지 검증한다.
- best-effort 화면 이벤트 이름과 product·position의 현재 세션 소속을 검증한다.
- choice, input method, 상태 전이는 allow-list로 검증한다.
- 종료 및 restart는 행 잠금 또는 동등한 낙관적 동시성 제어로 중복 활성 세션을 방지한다.
- 회원가입 요청의 기존 크기 제한과 role/status 필드 거부 규칙을 유지한다.

## 테스트 전략

### 서버 단위·통합 테스트

- 후보 자격 조건과 인기·최신 후보 풀 구성
- 카테고리·마켓·가격대 다양성 및 제약 완화 순서
- 동일 seed의 결정적 순서와 회원별 순서 분산
- `NOT_STARTED`, `IN_PROGRESS`, `COMPLETED`, `SKIPPED` 상태 전이
- 응답 upsert, 삭제, 카운터 원자성, 종료 요청 멱등성
- 다른 회원 세션 또는 세션 외 상품 접근 거부
- O/X 가중치, 시간·행동 감쇠, 부정 감점 30% 상한
- O가 없는 세션의 인기 상품 fallback
- 즉시 추천 실패 후 상태 보존과 Temporal 재시도
- 회원가입 응답의 토큰과 온보딩 상태 계약

### 프론트엔드 단위·컴포넌트 테스트

- 스와이프 거리와 속도 임계값
- O/X 버튼과 방향키의 동일한 choice 생성
- 실행 취소와 직렬 저장 큐
- 진행률, 첫 안내, 저장 상태, reduced motion
- 일부 응답 후 건너뛰기
- 서버 세션에서 재개할 때 첫 미응답 카드 선택
- 후보·저장·종료 오류 상태와 쇼핑 이동 경로

### E2E 테스트

- 회원가입 → 자동 로그인 → 10개 완료 → 개인 추천 홈
- 회원가입 → 즉시 건너뛰기 → 인기 상품 홈
- 일부 응답 → 브라우저 재방문 또는 재로그인 → 이어서 완료
- PUT 실패 후 재시도와 중복 없는 저장
- 완료 추천 생성 실패 후 fallback 홈
- 마이페이지에서 취향 다시 설정

## 단계적 출시

1. 기능 플래그 뒤에서 내부 계정으로 API와 E2E를 검증한다.
2. 신규 고객 가입의 10%에 노출하고 가입 완료율, API 오류율, 완료율을 확인한다.
3. 이상이 없으면 25%, 50%, 100% 순으로 확대한다.
4. 오류율 또는 가입 완료율 비열화가 기준을 넘으면 노출 플래그를 끄되 이미 생성된 세션과 응답은 보존한다.

기존 회원은 rollout 비율 계산 대상이 아니며 자동 노출하지 않는다.

## 인수 기준

- 신규 고객은 가입 성공 후 별도 로그인 없이 온보딩에 진입한다.
- 정상 카탈로그에서는 중복 없는 균형 상품 10개가 같은 세션에서 안정적으로 유지된다.
- 스와이프, 버튼, 키보드가 동일한 O/X 결과를 저장한다.
- 사용자는 어떤 단계에서든 건너뛰고 쇼핑을 시작할 수 있다.
- 새로고침과 재로그인 후 마지막 서버 저장 지점부터 이어서 평가한다.
- 완료 직후 O 기반 추천을 제공하고, 추천 생성 실패 시 인기 상품을 제공한다.
- X 하나가 카테고리 전체를 차단하지 않으며 부정 감점은 30% 상한을 지킨다.
- 실제 행동 20개 또는 90일 경과 후 온보딩 신호의 영향이 사라진다.
- 완료·건너뛰기 세션은 자동 재노출되지 않고 마이페이지에서만 다시 시작된다.
- 인증, 상태 전이, 멱등성, 접근성, 오류 fallback을 자동 테스트로 검증한다.
