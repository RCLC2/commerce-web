# 날씨 기반 `오늘의 코디` 장비창 설계

- 날짜: 2026-08-28
- 상태: 대화와 시각 시안에서 설계 승인 완료, 구현 전 문서 검토 대기
- 기준 브랜치: `origin/main`
- 구현 브랜치: `feat/today-outfit-weather`

## 1. 배경

현재 고객용 하단 탐색은 모바일 화면에서만 노출되고, `트렌드관` `/snapshot`은 서버가 제공하지 않는 `/api/v1/trends/posts`를 호출해 404를 발생시킨다. 새 `오늘의 코디` 화면은 사용자의 현재 지역 날씨를 기준으로 부위별 상품을 추천하는 탐색 진입점이다.

첫 구현에서 날씨는 실제 예보를 사용하고, 코디와 상품 조합은 백엔드 추천 계약이 생기기 전까지 프론트 픽스처로 제공한다.

## 2. 목표

1. 데스크톱과 모바일 모두에서 7칸 하단 메뉴를 항상 노출한다.
2. `카테고리 · 트렌드관 · 오늘의 코디 | 홈 | 좋아요 · 장바구니 · 마이페이지` 순서를 사용한다.
3. 사용자 위치의 현재 날씨와 7일 예보, 주간 평균 온도를 표시한다.
4. 시간대에 따라 새벽·낮·노을·밤 날씨 배경을 적용한다.
5. 여성과 남성 각각 10개의 더미 코디를 제공한다.
6. 캐릭터와 부위별 상품 슬롯 전체가 하나의 패널로 좌우 슬라이딩되게 한다.
7. 위치 권한과 외부 날씨 장애가 있어도 서울 기준 폴백으로 화면을 유지한다.
8. 오류 나는 `/api/v1/trends/posts` 호출을 완전히 제거한다.

## 3. 비목표

- 백엔드에 코디 추천 엔진을 추가하지 않는다.
- 사용자 성별 정보를 계정에 저장하지 않는다.
- 의류 이미지를 캐릭터 렌더링에 합성하지 않는다. 첫 버전은 캐릭터 배경과 주변 상품 슬롯을 표시한다.
- 실시간 재고·가격·개인화 로직을 더미 코디에 연결하지 않는다.
- 외부 날씨 제공자를 관리자 설정으로 바꾸는 기능은 포함하지 않는다.

## 4. 탐색과 헤더

### 4.1 하단 메뉴

`AppShell` 하단 메뉴는 다음 7개 항목을 가진다.

1. `카테고리` → `/categories`
2. `트렌드관` → `/snapshot`
3. `오늘의 코디` → `/today-outfit`
4. `홈` → `/`
5. `좋아요` → `/likes`
6. `장바구니` → `/cart`
7. `마이페이지` → `/mypage`

`md:hidden`을 제거하고 그리드를 7열로 바꾸며, 홈 버튼은 가운데 원형 강조를 유지한다. 푸터는 모든 뷰포트에서 하단 메뉴 높이만큼 여백을 가져 가림을 방지한다.

### 4.2 역할 전용 헤더 아이콘

기존 조건부 아이콘을 유지한다.

- `SELLER`: 셀러 콘솔 `/seller`
- `ADMIN`: 어드민 콘솔 `/admin`
- 일반 고객·비로그인: 역할 전용 아이콘 없음

역할 아이콘과 별개로 기존 장바구니·마이페이지 헤더 진입점은 유지한다.

### 4.3 트렌드관

`/snapshot`에서 Instagram 트렌드 무한 쿼리와 `catalogApi.listTrendPosts`를 제거한다. 화면은 서버가 지원하는 `/api/v1/search/trending`의 인기 검색어를 성별 탭으로 보여주고, 검색어를 누르면 통합 검색 결과로 이동한다. 이로써 `/api/v1/trends/posts`는 런타임·API 코드·테스트에서 더 이상 참조되지 않는다.

### 4.4 카테고리관

현재 카테고리관은 첫 요청부터 `category=outer`를 강제한다. 배포 데이터에 해당 slug가 없거나 서버 기본값과 다르면 전체 화면이 오류가 된다. 첫 `/api/v1/category-information`은 `category`를 보내지 않아 서버가 유효한 기본 카테고리를 선택하게 한다. 응답의 `selected_category.slug`를 현재 선택으로 사용하고, 사용자가 카테고리를 누른 뒤에만 명시적 slug를 보낸다. 오류·재시도 UI는 유지한다.

## 5. 날씨 데이터

### 5.1 위치 흐름

`/today-outfit`에 처음 진입하면 브라우저 `navigator.geolocation.getCurrentPosition` 권한을 요청한다.

- 성공: 위도·경도를 소수점 둘째 자리로 반올림한 뒤 자체 `/api/weather`로 전달한다.
- 권한 거부·미지원·시간 초과: 서울 시청 근처 좌표 `37.57, 126.98`를 사용한다.
- 위치는 서버·브라우저 저장소·세션에 저장하지 않는다.
- 정밀 위치 옵션을 요청하지 않고 적절한 시간 제한을 둔다.

화면은 현재 위치를 사용했는지 서울 폴백을 사용했는지 간단히 안내한다.

### 5.2 날씨 프록시

Next.js 라우트 핸들러 `GET /api/weather?latitude={lat}&longitude={lon}`를 추가한다.

1. 숫자 형식과 위도 `-90..90`, 경도 `-180..180` 범위를 검증한다.
2. 좌표를 서버에서도 소수점 둘째 자리로 정규화한다.
3. 고정된 Open-Meteo `https://api.open-meteo.com/v1/forecast` 엔드포인트만 호출한다.
4. 외부 응답을 Zod로 검증하고 프론트 전용 응답으로 정규화한다.
5. 좌표별 응답을 15분 단위로 재검증 캐시한다.
6. Open-Meteo 실패·타임아웃·스키마 오류는 안정적인 HTTP 오류로 반환한다. 프론트는 이를 받으면 내장된 서울 날씨 픽스처로 전환한다.

외부 요청 변수는 다음으로 고정한다.

- `current`: `temperature_2m`, `apparent_temperature`, `relative_humidity_2m`, `weather_code`, `is_day`
- `daily`: `weather_code`, `temperature_2m_max`, `temperature_2m_min`, `temperature_2m_mean`, `precipitation_probability_max`, `sunrise`, `sunset`
- `timezone=auto`, `forecast_days=7`

응답 하단에 Open-Meteo 출처 링크를 표시한다.

### 5.3 주간·오늘 표시

- 주간: 7일 날짜, 날씨 아이콘, 최고·최저 온도
- 주간 평균: 7개 `temperature_2m_mean`의 산술 평균을 반올림
- 오늘: 현재·체감 온도, 습도, 강수 확률, 오늘 최고·최저 온도
- WMO 날씨 코드를 맑음·구름·비·눈·뇌우 표현으로 변환

### 5.4 시간대 테마

현재 위치의 타임존과 오늘 일출·일몰을 기준으로 테마를 계산한다.

- `dawn`: 일출 90분 전부터 일출 45분 후
- `day`: `dawn` 종료 후부터 일몰 60분 전
- `sunset`: 일몰 60분 전부터 일몰 45분 후
- `night`: 나머지 시간

테마는 날씨 카드의 배경 그라데이션·조명·별·해 표현만 변경한다. 텍스트 대비는 모든 테마에서 유지한다.

## 6. 오늘의 코디

### 6.1 더미 데이터

별도 픽스처 모듈에 여성 10개와 남성 10개 코디를 정적으로 정의한다. 각 코디는 다음 필드를 가진다.

- 식별자, 성별, 코디 제목, 날씨 추천 이유
- 캐릭터 색상·스타일 토큰
- 부위별 상품: `head`, `accessory`, `outer`, `top`, `bottom`, `bag`, `shoes`
- 상품 이름, 표시 가격, 이미지 또는 프론트 플레이스홀더

첫 버전의 더미 슬롯은 존재하지 않을 수 있는 상품 ID로 연결하지 않는다. 클릭 시 행동은 후속 추천 API 계약이 정의된 뒤 연결한다.

### 6.2 성별 선택

- 코디 제목 우측에 `♀`, `♂`, `다른 코디` 제어를 함께 배치한다.
- 기본은 `♀`이며 선택 상태를 텍스트 외의 색상·배경으로도 표시한다.
- 두 기호에 각각 `여성 코디`, `남성 코디` 접근성 이름을 제공한다.
- 성별 전환 시 해당 성별의 첫 코디로 이동한다.

### 6.3 장비창 슬라이더

슬라이드 한 장은 캐릭터 배경, 7개 부위 슬롯, 코디 이유를 함께 포함한다. 전환 시 이 패널 전체가 수평으로 이동한다. 날씨 영역과 하단 메뉴는 이동하지 않는다.

입력 방법은 다음을 모두 지원한다.

- 터치·트랙패드 좌우 스와이프
- 이전·다음 화살표
- `다른 코디`: 다음 코디, 10번 뒤에는 1번으로 순환
- 하단 점 인디케이터 10개: 현재 점 강조, 각 점 클릭 시 해당 코디로 이동
- 키보드 좌·우 화살표

슬라이더는 현재 인덱스와 총 10개를 접근성 텍스트로 제공한다. `prefers-reduced-motion` 환경에서는 슬라이딩 애니메이션을 즉시 전환으로 바꾸는다.

### 6.4 반응형

- 넓은 화면: 캐릭터를 중심으로 좌·우에 상품 슬롯을 배치한다.
- 좁은 화면: 캐릭터 영역을 유지하고 슬롯은 양쪽에 축소 배치하되, 터치 대상은 최소 44px을 유지한다.
- 7칸 하단 메뉴 라벨은 매우 좁은 화면에서 아이콘 중심으로 축소하되 `aria-label`을 유지한다.
- 페이지 본문과 푸터에 하단 메뉴만큼 안전 여백을 적용한다.

## 7. 오류·로딩·폴백

- 위치 확인 중: 서울 기준 스켈레톤을 즉시 표시하고 위치 확인을 백그라운드에서 진행한다.
- 위치 권한 거부: 서울 날씨를 표시하고 `서울 기준`을 알린다.
- 날씨 API 장애: 내장 날씨 픽스처와 `날씨 정보를 업데이트하지 못했습니다` 안내, 재시도 버튼을 표시한다.
- 코디 더미 데이터는 네트워크와 무관하게 항상 표시한다.
- 슬라이더 상태는 성별 전환과 데이터 갱신 중에도 유효한 인덱스를 유지한다.

## 8. 보안·개인정보·운영

- 위치 정보는 화면에 진입했을 때만 요청하고 영구 저장하지 않는다.
- 서버로 보내는 좌표는 약 1km 수준으로 축소한다.
- 프록시는 사용자가 입력한 URL을 호출하지 않고 고정 Open-Meteo 호스트와 허용 변수만 사용한다.
- 잘못된 좌표는 400으로 거절한다.
- 현재 날씨 응답을 15분 캐시해 외부 호출과 렌더링 지연을 줄인다.
- 외부 제공자 라이선스와 서비스 제한은 배포 전 다시 확인한다.

## 11. 완료 기준

- 모든 뷰포트에서 7칸 하단 메뉴가 보이고 본문과 겹치지 않는다.
- `/api/v1/trends/posts`를 호출하는 코드와 테스트가 없다.
- 트렌드관은 지원되는 인기 검색어 데이터로 정상 표시된다.
- 카테고리관 첫 요청은 서버 기본 카테고리를 사용하고, 배포 데이터에 없을 수 있는 `outer` slug를 강제하지 않는다.
- 위치 허용 시 현재 지역, 거부 시 서울, 날씨 장애 시 내장 픽스처가 표시된다.
- 주간 예보·주간 평균·오늘 온도·체감 온도·습도·강수 확률과 시간대 배경이 표시된다.
- `♀`, `♂` 각각 정확히 10개의 코디가 있다.
- 캐릭터·7개 슬롯·코디 이유가 좌우로 함께 이동한다.
